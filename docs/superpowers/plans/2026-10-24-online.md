# Online multiplayer implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans for the owned task. Do not edit another owner's files.

**Goal:** Play the existing game with friends through GitHub Pages, room codes, Arabic, editable matches and hidden death roles.

**Architecture:** Trusted browser host runs the authoritative game. Each peer receives a sanitized projection with its own player remapped to 0, retaining the existing renderer and local controls. PeerJS handles transport; explicit offline/error states replace fake multiplayer.

**Tech stack:** Vanilla JavaScript, Canvas, WebAudio, WebRTC/PeerJS, Node tests and Playwright.

**Spec:** docs/superpowers/specs/2026-10-24-online-design.md

## Global constraints
- 4–12 human players; no bot gameplay.
- No public role on death; final results may reveal roles.
- Role/visitor privacy applies to wire data, not only visible UI.
- Arabic/English and RTL; player messages/names are preserved.
- GitHub Pages static hosting; host remains open; configurable TURN.

## Review focus
- Malformed/spoofed actions must not control another participant.
- An ordinary client's payload must not contain other secret roles/intel.
- Reconnect must reuse the seat only with its secret token; host loss is visible.
- Private night timing must not publish death outcomes before dawn.
- Arabic controls remain usable on a 390px screen.
